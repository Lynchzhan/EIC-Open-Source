# 记忆候选索引与 Langfuse 批量投递

本页说明记忆检索索引与 Langfuse 持久批量投递的实现及启用注意事项。启用相关能力前，应按目标环境迁移数据库、准备索引并完成回填。ANN 召回质量及大规模性能收益需要使用目标数据单独评估。

## 索引职责

关系库仍是正文、授权、版本、有效期和遗忘状态的唯一权威。索引只生成候选，不能授予访问权限。

| 数据 | 存储 | 用途 |
| --- | --- | --- |
| 词项索引头 | memory_search_documents | 记忆版本、正文哈希、分词版本 |
| 词项倒排 | memory_search_terms | 英文词与中文二元词的 SHA256，生成稀疏候选 |
| PG 投影回执 | memory_projection_receipts | 向量 ID、正文哈希、投影版本与单调代次 |
| PG 投影 | public.eic_memory_vectors | 向量、归属和来源 ID，不存正文 |
| PG 写入栅栏 | public.eic_memory_projection_heads | 拒绝迟到的低代次写入或清理 |

稀疏候选上限 60，PG 候选上限 240，稠密候选复核后取前 60。候选复核只读向量的 ID、版本、哈希，不把整块向量 JSON 搬回 Python。之后读取候选正文并沿用 RRF、冲突赢家与发送前快照复核。

归档、纠正、遗忘和会话删除会同事务撤销词项或登记投影同步。会话短期记忆按每批 100 个 ID 清理，长期记忆保留。PG 写入在关系库事务提交后执行；成功后再复核来源与消费租约，确认回执。迟到的回执提交不能删除更高代次回执。
曾投影的记忆在关闭投影后被遗忘，也会保留清理意图。关闭期间不调度 PG I/O；重新启用后再消费。已经进入旧队列的关闭任务改用新持久身份等待，不消耗失败重试次数。关闭投影不表示远端派生数据已经物理清除。

当前 HNSW 合同支持 1–2000 维。PG 候选查询有 statement_timeout 和外层预算；超时、投影未启用或缺回填收据时使用原有界路径。ANN 是近似检索，仍需真实数据评估召回率；不能把索引存在当成质量证明。

## 启用顺序

1. 在隔离数据库副本验证 Alembic 0042_memory_search 迁移，再按正式发布流程升级。启动只检查 schema，不自动迁移。迁移仅加三张关系表，不回填正文，不请求模型。
2. EIC_MEMORY_CANDIDATE_INDEX_ENABLED 默认 true，只控制召回采用词项候选；写入仍维护索引。即使关闭此开关，新代码也要求新 schema。
3. 在记忆面板点击“重建检索索引”，将当前用户、Agent 范围内的已有记忆分批回填。没有向量模型调用；已有向量不会被重新生成。
4. 需要独立向量候选时，先在目标 PG 准备基础表和实际维度的 HNSW。EIC_VECTOR_DATABASE_URL 必须指向已确认的目标，不要照抄示例账号。

以下命令从仓库根目录执行，使用项目已锁定的后端环境。先在隔离环境核对数据库连接和目标维度：

```powershell
uv run --frozen --project backend python scripts/prepare-memory-projection.py --dimensions 1536
```

5. 显式设置 EIC_MEMORY_VECTOR_PROJECTION_ENABLED=true。若限定了 EIC_OUTBOX_DISPATCH_KINDS，须包含 memory-projection。消费者需要 PG 访问权限，普通 API 写事务不直接连接 PG。
6. 再次执行“重建检索索引”，登记已有向量的同步意图。回填期间缺少回执的作用域继续走有界旧路径；等待同步完成后，再验证 candidateSource、indexFallback 和结果。

重建接口：POST /api/AIAgentMemory/RebuildSearchIndex，需要 memory.write，只能处理当前用户记忆。传入 sessionId 或 agentId，以及 afterId（首批为字符串 0）。每批最多处理 100 条，返回 indexed、projectionQueued、hasMore、nextAfterId；循环时检查游标前进。sessionId 会校验归属并确定 Agent，短期记忆仅限该会话。支持重复提交，不补发 embedding。

“重建向量索引”仍是原来的独立操作，可能申请模型预算并调用 embedding；与“重建检索索引”含义不同。

投影同步失败或租约过期时创建新的持久事件和队列身份，延后 30 秒，最多自动补投 4 次。耗尽后以 memory_projection_retry_exhausted 结束自动重试，排除 PG 配置、连接或维度问题后显式重建。不会通过重试投影补发模型请求。

## 重建与恢复边界

PG 表是派生数据，不替代关系库备份。若重建、清空或更换 PG，而关系库保留旧回执，应先关闭投影召回，停住旧投影写入者，按经过审查的恢复流程撤销旧回执并回填，再启用。不要只复制回执而不复制投影。

从旧备份恢复关系库时，还要核对 PG generation 栅栏；旧 allocator 值不能绕过更高代次。不可在运行中直接清空栅栏或删除权威记忆。正式恢复点应覆盖停写窗口内的关系库、向量库、上传文件和原配置；普通在线副本不能代替跨存储的一致性备份。

SQLite 发布适配器保留 0039→0041 原计划，并增加 0039→0042、0041→0042 的纯加表计划；精确 fromHead/toHead、表集合、旧数据指纹和空新增表仍须核验。其它迁移路径不自动接受。新脚本字节、schema 和镜像形成新发布候选，旧批准哈希不能复用。

## Langfuse 持久批量投递

已落盘的投递行通过 CAS 有界领取；默认目标大小沿用 EIC_LANGFUSE_BATCH_SIZE，单次最多领取 128 个业务行。一个业务事件的所有导出对象不拆批；容量不足的事件确定尚未发送，会 deferred 回队，不消耗尝试次数。单个事件最多 256 个对象、单对象 256 KiB、整批保留包装预算后不超过 3,000,000 字节。单事件可超过目标批大小，但仍受硬上限约束。

同一次 HTTP POST 后逐业务事件核对全部对象：全部明确成功才 acknowledged；全部明确 429 才可安全重试，最多 5 次。部分成功、缺项、5xx、超时或未知响应保留 unconfirmed，不自动重发整个事件。进程取消或崩溃遗留的 sending 在租约过期后也进入 unconfirmed。acknowledged 只表示传输接收回执，仍须另行核对 Langfuse 远端可见性。

诊断 lastBatchSize 为本次领取的业务行数；lastDispatchMs、最老积压时间和各持久状态用于观察。进程内 acceptedEvents 等计数按导出对象计数，不能与业务行数直接比较。

持久批量投递不需要新增第三方依赖；沿用原有身份、脱敏转换器与可选 OTLP 出口。普通观测入口在独立本地提交前仍有内存队列丢失窗口，本次没有把所有观测改成强制同步写入。不能据此宣称全链路零丢失。

## 验证建议

迁移后检查新增表和索引，再用合成数据验证回填、作用域隔离、分页游标、迟到写栅栏和 Langfuse 响应处理。若启用 PG 投影，应以目标向量维度准备 HNSW 并测量实际召回质量。构建、固定集回归、真实数据库、真实模型、Langfuse 远端可见性及生产容量属于不同验证范围，应分别记录结果。
